# Рефакторинг

Рефакторинг делает код проще для чтения, изменений, отладки и проверки без изменения внешнего поведения. Разделяет несвязанные обязанности, упрощает эндпоинты и хуки, убирает лишние слои и тесты без реальной пользы. В конце новый саб-агент ставит оценку от 1 до 10 и ищет пропущенные улучшения и проблемы DX. После исправлений ревью повторяется с новыми саб-агентами, пока проблемы DX не перестанут появляться. Максимум — пять кругов ревью.

## Установка

Отправьте агенту это сообщение.

```text
Установи скилл глобально
https://github.com/di-sukharev/refactoring-skill
```

## Запуск

Напишите `отрефактори` в чате, где агент писал код. Можно указать конкретные файлы или часть проекта. Без конкретной цели скилл работает с активными изменениями Git, а если их нет — просматривает проект целиком.

При просмотре проекта сначала идут исходные файлы длиннее 1000 строк, затем оставшиеся длиннее 500, 200 и 100 строк. Размер определяет порядок просмотра, а не обязательный лимит строк. Сгенерированный и сторонний код пропускается.

После реализации задачи агент может применить скилл к написанному коду. Критерий пользы — код проще читать, изменять, отлаживать или проверять. Если такой пользы нет, правки не нужны.

## Другие скиллы

- [Code Scout](https://github.com/di-sukharev/code-scout-skill) — саб-агент ищет код — дешёвый агент поглупее ищет нужный код и приносит его умному агенту, чтобы тот не тратил свой дорогой контекст.
- [Orchestration](https://github.com/di-sukharev/orchestration-skill) — выполняет несколько крупных задач отдельными саб-агентами: каждый планирует, реализует и запускает независимое ревью через Loop Code Review.
- [Loop Code Review](https://github.com/di-sukharev/loop-code-review-skill) — ревью только что написанного кода в цикле — саб-агенты без контекста в цикле находят и исправляют проблемы в активных изменениях.
